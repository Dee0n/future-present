# Menuless E on NPCs in Skyrim SE 1.5.97, and Sanguine as an actor (research, 2026-10-09)

Method note: Nexus Mods pages and ck.uesp.net / skyrimck.uesp.net returned HTTP 403 to the fetch tool, and creationkit.com redirects to a maintenance page. CK wiki claims below come from search-result summaries of those pages or from cs.uesp.net, and are labelled "read via search summary" where the page itself was not opened. Source for CHIM code is the `main` branch of Dwemer-Dynamics/CHIM, not the 3.4.2 tag. Not verified by running anything in-game.

## 1. Does CHIM offer menuless activation?

Result: no option found. CHIM 3.4.2 offers no setting that stops the vanilla DialogueMenu from opening when the player presses E.

- The Plugin directory has no hook on NPC activation. In `Plugin/Plugin.cpp` (494,344 chars, all read in 100k chunks) the only activation code is an event sink: `On<RE::TESActivateEvent>` that logs "[ACTIVATION] Player activates ..." and handles doors and "Chim Portal". An event sink observes activation; it cannot cancel it. (read, CHIM main branch) https://raw.githubusercontent.com/Dwemer-Dynamics/CHIM/main/Plugin/Plugin.cpp
- The plugin installs these hooks on non-VR runtimes: `ProcessorActorDialogue::InstallHooks()` (write_vfunc slot 0x4C on Actor and Character, `UpdateInDialogue`) and `ProcessorDialogueMenu::InstallHooks()` (write_vfunc slot 0x4 `ProcessMessage` and 0x5 `AdvanceMovie` on `RE::DialogueMenu`). Their job is the "player menu TTS" feature: delay and replay topic selection, hold the NPC line. They do not prevent the menu from opening. The function `TryInterceptPlayerMenuSelection` starts with `return false;`, so it is disabled. Same file as above.
- Config flags seen there: `PlayerTtsTraditionalDialogueEnabled`, `CaptureBackgroundChatEnabled`, `AIQuestProgressionEnabled`, `ENABLE_AUTOADDNPC`, `CombatDialogueEnabled`, `CancelDialogueOnCombat`. None of them names menuless activation. (read, same file)
- "Menuless Questing" (changelog 3.1.4) is implemented as server-approved quest actions applied through `AIAgentQuestProgressionBridge.psc` (`StartQuest`, `SetQuestStage`, `SetQuestStageObjective`, `StartScene`, objective setters). The script has no activation or menu code. It advances quests by script while the AI speaks; it does not open or suppress menus. (read) https://raw.githubusercontent.com/Dwemer-Dynamics/CHIM/main/AIAgent/Source/Scripts/AIAgentQuestProgressionBridge.psc
- `Plugin/Conf.cpp` reads only four ini keys from `Data/SKSE/Plugins/AIAgent.ini`: SERVER, PATH, PORT, POLINT. Other options live on the server side (not re-read by me; you already read it). (read) https://raw.githubusercontent.com/Dwemer-Dynamics/CHIM/main/Plugin/Conf.cpp
- `Plugin/PlayerConversationRouter.cpp` only picks the responder (crosshair via `RE::CrosshairPickData`, options `AutoAddAllRaces`, `AutoAddHostile`, `CombatDialogueEnabled`, `AllowActorsOnScene`). No hooks. (read) https://raw.githubusercontent.com/Dwemer-Dynamics/CHIM/main/Plugin/PlayerConversationRouter.cpp
- Public docs: the repo ships only `AIAgent/docs/CHIM/{AGENTS,agent-guide,building,custom-plugins}.md`; `agent-guide.md` has no text on dialogue menu or activation. (read) https://raw.githubusercontent.com/Dwemer-Dynamics/CHIM/main/AIAgent/docs/CHIM/agent-guide.md . Repo list: https://github.com/Dwemer-Dynamics . Repo README: https://github.com/Dwemer-Dynamics/CHIM
- The Patreon page shows only the 3.4.2 post (voice filters, Hypnosis Mode); it does not carry the 3.1.4 or 3.3.2 entries. https://www.patreon.com/dwemerdynamics
- Limits: I did not read `Misc.cpp`, `Papyrus.cpp`, `Commands.cpp`, `SpeakManager.cpp`, or the AIAgent ESP scripts, so a toggle for "creature auto-activation" (3.3.2) could exist there. It is unconfirmed what that toggle does. CHIM's own tooling also allows plugins: `custom-plugins.md` and https://github.com/Dwemer-Dynamics/CHIM-Custom exist but were not read.

## 2. How existing mods handle the menu on 1.5.97

- Mantella (Python app plus Papyrus mod "Mantella-Spell"): starts a conversation with a spell, a power, a hotkey (enabled in the MCM), or the vanilla dialogue menu. The docs do not mention suppressing the menu. The repo's Papyrus sources include `MantellaVanillaDialogue.psc`, `MantellaListenerScript.psc`, `MantellaEffectScript.psc`; SKSE HTTP plugin (Leidtier) and a "Mantella Dialogue" plugin are listed as requirements. Mantella works around the menu by not using E at all. (read; Mantella docs for v0.12+, repo state of 2026) https://art-from-the-machine.github.io/Mantella/pages/installation.html , https://github.com/art-from-the-machine/Mantella-Spell/tree/main/Scripts/Source , https://github.com/art-from-the-machine/Mantella-Spell
- Enderal SE (SKSE DLL, CommonLibSSE style): `DialogueMenuPatch::Install()` replaces vtable slot 0x4 (`ProcessMessage`) of `RE::DialogueMenu` via `vtbl.write_vfunc(0x4, &ProcessMessageEx)`, and returns `UI_MESSAGE_RESULTS::kIgnore` for Tab/Esc key events. Established pattern for filtering messages to the DialogueMenu; this one filters keys, not opening. Applies to Enderal SE (Skyrim SE 1.5.97 era DLL, commit page undated in my read). https://git.eddoursul.win/enderal/enderalse/commit/13635df9f80c60af99c6d9bda016735c80806815
- Same repo, commit "Open journal in locked dialogs": the author commented out `UIMessageQueue::AddMessage(..., kShow, ...)` for the journal because it disturbed the dialogue UI (search-result summary only). https://git.eddoursul.win/enderal/enderalse/commit/467852f52ecb684ec113a0dcebe505278e73c7af
- Skyrim Souls RE: does not touch DialogueMenu (README: menus unpaused by default, "like DialogueMenu or CraftingMenu", are not covered). Not a menu blocker. (read) https://github.com/Vermunds/SkyrimSoulsRE/wiki
- Dialogue-skip SKSE plugins (Nexus 89163, 115331) shorten the 750 ms greeting delay; they do not suppress the menu. Nexus pages not opened (403); from search summaries only. https://nexusmods.com/skyrimspecialedition/mods/89163 , https://www.nexusmods.com/skyrim/mods/115331
- No existing mod that suppresses the menu on E was found (see Not found).

## 3. Papyrus-only routes

Game default: activating an NPC runs Dialogue unless the RunOnActivateFlag is 1, in which case the OnActivate block runs instead. (read, CK wiki mirror, applies to Skyrim CK generally) https://cs.uesp.net/wiki/Activate

| Route | Stops DialogueMenu for NPCs? | Breaks |
|---|---|---|
| `ObjectReference.BlockActivation(true)` | Blocks normal activation processing, so E on the NPC does nothing by default; `OnActivate` still fires on the script that set it. The activate prompt stays visible. Linked refs take over activation. (CK wiki, read via search summary of ck.uesp.net/wiki/BlockActivation_-_ObjectReference; page itself 403) | Every normal interaction with that NPC: no vanilla dialogue, barter, follower commands, pickpocket (sneak-E is also activation), quest greetings that start from E. Must be set per reference, and re-set after load or cell reset (BlockActivation from alias scripts is not auto-removed). A Nexus thread says any true/false combination also prevents OnActivate in some cases and suggests a perk plus `Self.BlockActivation()` instead (search summary of forums.nexusmods.com/topic/13490297; 403, unconfirmed) |
| `OnActivate` on NPC script | Does not stop the menu by itself. Script event is run in addition to or instead of default depending on RunOnActivateFlag; a Nexus modder reports a script that "did play but unfortunately it didn't block the dialogue" (search summary, unconfirmed) | Per-ref script needed; can't be put on every NPC without a quest alias or a perk |
| Perk entry point "Activate" (Replace Activation) | Not verified. Perk entry "Activate" on the player can replace the default activation of a target; I found no source that tests it on NPC dialogue. | Not found |
| `Game.DisablePlayerControls(abActivate=true)` | Stops the player activating anything (movement flag also stops activation). Source: CK wiki, Skyrim signature `(abMovement, abFighting, abCamSwitch, abLooking, abSneaking, abMenu, abActivate, abJournalTabs, aiDisablePOVType)`, read via search summary of https://ck.uesp.net/wiki/DisablePlayerControls_-_Game | Blocks E for doors, containers, and pickups too, so the mod would need its own re-enable; no way to allow only NPCs |
| Close the menu after it opens (`UI.CloseCustomMenu`, `UI.Invoke("Dialogue Menu", ...)`) | Not verified. `CloseCustomMenu` applies to custom menus only (my reading, not sourced). `StartHideMenu` exists as the DialogueMenu ActionScript hide function (Nexus article 10444, search summary). No source shows a working Papyrus call. Even if it works, the menu opens first: flash, paused HUD, and the NPC's greeting voiceline plays. | Quest-forced greetings and scenes still run and fight with the closing; flicker |

Papyrus verdict: Papyrus can hide E on an NPC (BlockActivation) and catch the press (OnActivate), so a Papyrus-only design that replaces E is possible for chosen NPCs. It cannot cleanly keep other E behaviour (barter, followers, pickpocket, quest greetings). No Papyrus route found that cancels the menu for all NPCs.

## 4. SKSE C++ routes with CommonLibSSE(-NG)

All signatures read from CommonLibSSE-NG `main` headers; offsets for 1.5.97 resolve through Address Library (NG supports SE/AE/VR in one DLL; CHIM README says the same, https://github.com/Dwemer-Dynamics/CHIM). Vtable slots are SE and AE identical in these headers.

- `TESNPC::Activate` (and `TESBoundObject::Activate`): `bool Activate(TESObjectREFR* a_targetRef, TESObjectREFR* a_activatorRef, std::uint8_t a_arg3, TESBoundObject* a_object, std::int32_t a_targetCount) override;` vtable slot 0x37. Hooking slot 0x37 of the TESNPC vtable and returning true (after starting your own conversation) skips vanilla NPC dialogue, with a pass-through to the original for non-targets. This is the cleanest cut: no menu ever opens. No shipped plugin that does this was found, so it's design from headers, not an "established" hook. https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/T/TESNPC.h , https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/T/TESBoundObject.h
- `ActivateHandler` (player input handler): `CanProcess` slot 01, `ProcessButton(ButtonEvent*, PlayerControlsData*)` slot 04, has a `disabled` byte at 0x1B. Hooking `ProcessButton` lets the plugin see the E press and check `CrosshairPickData` first. https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/A/ActivateHandler.h
- `TESObjectREFR::ActivateRef(activator, arg2, object, count, defaultProcessingOnly)`, non-virtual, plus `SetActivationBlocked` / `IsActivationBlocked`. https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/T/TESObjectREFR.h
- `DialogueMenu::ProcessMessage` slot 04 hook (Enderal, CHIM both use it): can swallow messages but the menu is already created. `UIMessageQueue::AddMessage(const BSFixedString&, UI_MESSAGE_TYPE, IUIMessageData*)` is the call that opens menus; filtering `DialogueMenu` kShow there is not documented in any source I found (Enderal's author removed a kShow call due to UI side effects). https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/U/UIMessageQueue.h , https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/D/DialogueMenu.h
- `MenuTopicManager` (`speaker`, `isGreetingPlayer`, `currentTopicInfo`, singleton ID 514959 SE / 401099 AE) is state only: no `SetDialogueWith` in the header; useful for reading who the speaker is, as CHIM does. https://raw.githubusercontent.com/CharmedBaryon/CommonLibSSE-NG/main/include/RE/M/MenuTopicManager.h
- Event option: `TESActivateEvent` sink (CHIM uses it) fires on activation but cannot cancel it.
- Build inputs already exist: CHIM's repo builds on CommonLibSSE-NG with SkyrimScripting submodules and has `Plugin/` CMake presets, so its build guide `AIAgent/docs/CHIM/building.md` is a template for our own plugin. https://github.com/Dwemer-Dynamics/CHIM

## 5. Sanguine as an actor

- Sam Guevenne: BaseID 0001BB9C, RefID 000A96A0. Breton conjurer level 50, essential, spawns in an inn after level 14; quest DA14 "A Night To Remember". (read, UESP, Skyrim SE content, USSEP 4.3.9 notes) https://app.uesp.net/wiki/Skyrim:Sam_Guevenne
- Sanguine: BaseID 0002E1F2, RefID 0002E1F3 (the ref in Misty Grove). Essential, cannot be pickpocketed. Known bug: after the quest he may roam Morvunskar killing mages (USP 2.0.0 fixes). (read) https://app.uesp.net/wiki/Skyrim:Sanguine
- Quest page: DA14 stages split between `DA14Start` and `DA14` scripts; `setstage` and `resetquest` console steps documented; other listed bugs include Sanguine hostile if you arrive as a werewolf, and Sanguine sometimes not appearing. Page documents no duplicating or placing of Sam or Sanguine. (read) https://app.uesp.net/wiki/Skyrim:A_Night_To_Remember
- Does `placeatme 0002E1F2` outside the quest break DA14? Not found. By construction `placeatme` creates a new reference with the base record; the quest's reference (0002E1F3) and Sam's quest aliases stay on the original refs, so the quest should not be touched, but this is my reasoning, not sourced. Risks I can state from the sources: Sanguine is essential and carries quest-scoped dialogue conditions (no source read for these conditions).
- Safer alternatives (not sourced as tested): a plain Dremora (Dremora Lord via Sam's own spell Conjure Dremora Lord, from the UESP NPC page) renamed with a custom name, or a generic NPC with a shader/ghost effect. Reasoning: they have no quest dependencies. Sam's pre-reveal form (0001BB9C) is the less dangerous base for a human-looking Sanguine, but he is also quest-bound (essential, DA14 scripts).
- Cleanest design: create a new NPC record in our own ESP (copy Sanguine's appearance, no quest conditions), and assign it to CHIM as a normal agent. Requires Creation Kit work; no source needed.

## Ranked routes (questions 1-4), cheapest first

1. Papyrus: `BlockActivation(true)` plus `OnActivate` on a chosen NPC (or on NPCs a quest alias or the CHIM agent list picks), with the OnActivate handler calling the CHIM talk command. Cost: Papyrus in our existing mod. Breaks: all normal E interactions with that NPC (dialogue, barter, follower orders, pickpocket, quest greetings) and needs re-application after cell reset or load; the prompt text stays visible. Fits the "dedicated companion NPC" case, not "every NPC".
2. Papyrus plus controls: `Game.DisablePlayerControls(abActivate)` while a hotkey conversation runs; keep vanilla E for everything else. This is Mantella's effective answer (spell/hotkey instead of E). Cost: low. Breaks: no E-based menuless; hotkey is the trigger.
3. C++ SKSE plugin hooking `TESNPC` vtable slot 0x37 (`Activate`) or `ActivateHandler::ProcessButton` slot 04: starts the voice conversation and returns without opening DialogueMenu, passing through for merchants, followers, sneaking, and quest-forced cases that you list. Cost: high (new DLL; CHIM's repo is a working CommonLibSSE-NG build template). Breaks: only what your pass-through list misses; untested by any shipped mod I could find.

Answer on Papyrus alone: enough for named NPCs (route 1), not enough for global menuless E with vanilla functions preserved.
